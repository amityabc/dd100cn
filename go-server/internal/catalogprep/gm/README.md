# 原生 GM 资源准备

`gm.Build(ctx, pvf, profile, output)` 读取原始 `Script.pvf`、同目录 `sk.dat` 和匹配的客户端 profile，生成可供 Go 服务和原 GM 界面读取的 ZIP。GUI 的显示索引包含装备和堆叠物品的名称、模板 ID、分组和原始路径。按模板 ID 查询的分片保持 `Template`、`Error`、`Weight`、`Special` 字段。重量表保留资源明确给出的零重量，装扮克隆表保留原部位和资源 SHA-256。

生成器按 PVF 压缩块顺序遍历资源，然后写 256 个查询分片、显示索引、重量和克隆表。清单和显示索引的 `Parser` 沿用配套旧程序集的模块版本 ID `442f1c44-d683-4dcf-a601-159788063536`，原工具可继续校验已有缓存。PVF、sk.dat 和 profile 各自记录原始摘要。

匹配 S9A1 原始 PVF 的离线比对覆盖 292,895 条显示记录、160,971 条普通模板、129,682 条特殊模板、2,242 条原拒绝原因、160,952 条重量和 117,369 条装扮克隆，均与原 C# ZIP 逐字段一致。比对使用 ZIP 作为参考，生成器的输入是原始资源。

运行时，C176 与在线 GM 邮件共享普通模板预算，C176 的装扮、宠物和宠物装备另有专用预算。两类分别最多登记 32,768 个模板和 16 MiB 的旧 C# 紧凑 JSON，每个成功登记的模板只计一次。邮件只准备普通模板，离线队列校验使用当前命令的独立临时目录。ZIP 内的静态预编记录不计入这两类运行预算。

在线管理邮件首次登记的普通物品随当前服务进程发布相关背包规则。真实模板 1285 的离线排队和在线发放生成相同附件，在线发放后可按原规则丢弃，其他已在处理中的游戏请求继续使用原目录快照。C176 和玩家邮件的转移资格分别按各自的原入口判定。
