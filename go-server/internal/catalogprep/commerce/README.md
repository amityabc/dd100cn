# 原生商业资源准备

`commerce.Build(items, towns, options)` 从匹配的 S9A1 PVF 生成 schema 4 的 `Commerce`、`Weights`、`MailAttachments`、`Rename`、`GoldCarryLimits` 和两套现金购买限制。命令行总目录调用此入口。`NewItems` 解析装备与堆叠物品索引，其他模块可按来源使用 `Source`、`Ordinary`、`Prepared` 和 `Gift`。原始物品字节的 SHA-256 贯穿普通模板、特殊模板、交易资格与活动规则。

静态目录的物品根集来自城镇和副本商店、现金商城、任务材料与奖励、分解产物及已验证的原生入场和改名来源。构建器先冻结重量和邮件资格，再扩展礼包依赖与独立箱子目录。商店付款模板按旧目录规则进入最终普通模板表。任务成长预备项和洞察奖励装备参与消耗品、品质及打造的专有校验。`Options` 由总目录传入原生任务、战令、活动和品质数据。

匹配原始 PVF 的离线比对覆盖城镇商品 43,408 行、副本商品 144 行、现金商城 318 项、礼包 718 项、普通模板 5,776 项、邮件资格 4,630 项和重量 5,993 项。各自的生成阶段还核对了装扮、宠物、消耗品、箱子、命运商店、打造和品质的资源字段。商业目录按身份字段稳定排序，比较商店货品、共用商人和 NPC 可见性列表时按成员核对。旧 C# 输出只用于对照。

`BuildOwned` 供启动读取既有资产和游戏内 C176 发放时补充资源。启动使用已持有物品及其可验证依赖，补充使用、出售、修理、分解、打造、品质、重量与邮件资格。C176 使用单个目标及其发放依赖，并准备该目标的打造和使用规则。GM 的普通库存回退会先登记模板，再按原始资源计算邮件和丢弃资格。礼包发放使用各自冻结的奖励模板，已有普通模板保留自己的取得属性。增量发布在上层完成，购买目录仍由静态构建生成。
