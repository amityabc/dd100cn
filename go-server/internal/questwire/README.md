# 进城任务手册

首次加载城镇时，服务端读取所选角色的任务、普通背包和已提交的奖励收据。依次发送 N561 活动目标与剩余量、N21 可接任务和 N356 已清任务。N356 将 30,000 个标记用原服使用的 zlib-ng 实现压缩。

资源导出器从匹配版本 PVF 读取 2,905 个普通任务，以及装备图鉴、DPL 任务券和等级变更涉及的任务。职业、转职、等级、位置、已清前置、互斥选择及来源条件都会影响手册。材料任务只统计普通背包。含有进度的旧存档若缺少匹配的目标定义，投影会返回角色对应的任务号。城镇到达确认 C33 依赖已提交的到达收据。任务完成、扣除交付物、发奖及关联子任务属于事务命令。[资源导出器](../../tools/catalog-export/QuestExport.cs)

在持有匹配 PVF 的项目内，从 `go-server` 目录运行下列命令。测试比较 76 个建角模板在两个地点的可接清单，并用原 C# 的八组 1、30、50、51、75 和 100 级存档逐字节核对三种通知。样本包含非空狩猎与材料任务、不同答案的已清标记及 N356 压缩正文。[C# 样本生成程序](testdata/Program.cs)

```powershell
.\tools\export-characters.ps1
.\tools\go.ps1 test -count=1 -v ./internal/questwire
```

## 城镇接取与放弃

普通城镇准备完成后，C31 接取、C32 放弃都支持原始 2 字节任务号和带操作号前缀的 4 字节请求。C31 首次接取发送 ACK 和 N561、N21、N356。重复接取一个已活动任务时，同一角色会话先收到一次 ACK，之后静默。重选角色或重连会重新建立这项回包记录。C32 检查 PVF 的可放弃标志和活动子任务；放弃后再放弃，返回原错误正文 `00 07 00`。

当前 PVF 的 2,905 条普通任务中，2,874 条带可放弃标志，7 条使用每日周期。日切为 UTC+8 的 06:00。唯一接取时发物品的任务 5654 需要一份模板 4365。缺少时，道具和任务在同一数据库事务写入，旧服用 N14 的普通背包增量标记新道具。已有时 C31 返回现有槽号及绝对数量。放弃任务保留物品，再接取沿用同一实例。完整 Host 启动时逐条验证操作规则和接取物品模板；早期导出的 schema 4 目录缺少这些字段时，错误会提示重跑 `tools/export-characters.ps1`。

23 个旧服原始请求及其 64 个应答通过真实 TLS 网关在 PostgreSQL 副本上重放。逐包比较覆盖正常接取、重连、相同序号重发、准备完成前的拒绝、活动子任务阻止放弃、PVF 禁止放弃、未知任务及错误前缀。独立字段测试另检查请求长度。每次请求都对照角色任务 JSON、版本、物品属性、模板和 119 字节冻结核心。样本以独立的 v35 城镇角色为底本，测试设置为 100 级并预置 3248、5653、6211 三个已清前置，角色从版本 104 推进至 115。[旧 C# 原始记录](testdata/legacy-commands.json.gz)

以下命令在已有城镇测试存档及匹配 PVF 的 `go-server` 目录运行。每次从同一存档导入一个新测试库，将示例库名换成项目内尚未使用的名字。该录包对应 C31/C32。[实服验收程序](testdata/commands.py)

```powershell
.\tools\go.ps1 install ./cmd/serve100 ./cmd/multiplayer-admin
python -B .\internal\questwire\testdata\commands.py --prepare
$fixture = 'quest_cmd_' + (Get-Date -Format 'yyyyMMdd_HHmmss')
.\tools\go.ps1 run ./tools/postgres/importfixture -name $fixture -source ./.work/quest-commands/v35-town-quests.sqlite3 -account quest-wire-v35
$pgBin = Split-Path (Get-Process postgres | Select-Object -First 1 -ExpandProperty Path)
python -B .\internal\questwire\testdata\commands.py --dsn-file (Join-Path ..\.work\postgres-storage ($fixture+'-dsn.txt')) --libpq (Join-Path $pgBin 'libpq.dll')
```

## 触发、交付与成长

C33 保留普通回调的 6/7 字节正文，以及任务 3868、3869 的独立答题格式。范围目标读取已保存坐标与到达收据。问答在匹配的 NPC 场景中冻结选择，C34 保存 `答案 + 1` 的已清标记，并允许相同请求回放。副本的击杀、清图和剧情电影确认按当前迷宫及持久收据核对。

C34 在同一 PostgreSQL 事务扣材料与交付费，按 PVF 发放经验、金币、物品和技能点，更新任务状态并写入 `quest:<任务号>` 或每日任务收据。城镇的联合交付可提交末子和父任务。觉醒回复保留阶段与两个技能表，普通成功回复保留经验及原字段。收据按角色、任务哈希、原始选择与倍率核对，重放沿用已保存的经验奖励。

C1422/C1449 处理旧主线树。它以已保存答案和条件选出可清任务，只写任务标记。C507 action239 校验通信器、使用冷却、任务状态和目标场景，再写传送点及使用收据，由 C35 恢复城镇消息。C1261 在排位训练场按本次接取和已完成回合发手册，手册与对应训练进度一起提交。

C1422 非零值预览持有的 action77 或 action101 完成券。C507 任务券读取原 PVF 的作用范围、条件和冷却，核对本次动作与来源 UID。C130 兼容已存在的 6225～6229 和旧上篇 6413，允许 PVF 声明的功能卷轴及技能效果。奖励、冷却、角色任务及技能状态与扣券收据在同一事务提交。已退役的 6410～6412、8725/8726 和原服没有明确目标范围的辅助券按资源边界处理。

技能路由 C28/C29/C483/C260/C439/C331 从同一份 PVF 副本读取技能定义、初始等级和成长授予。普通技能页、第二页及决斗页保留各自的 SP/TP 和技能，训练专用覆盖页由本次会话管理。技能购买与重置以存档余额和每级消耗计算，支持技能前置、免费等级、任务折扣和觉醒等级限制。C29 在符合原服自动分配或训练请求时，同步提交任务阶段。

C494、C777、C1880 根据角色等级、职业分支、资金和实际使用的道具实例执行转职。C494 要求普通城镇准备完成，命运营地和已授权的命运活动不能使用该券。道具比对沿用原资源对同模板旧档的周删除日兼容，原期限和 119 字节核心继续用于校验。C30 经验书、C44 经验道具、C410 升级券和 C507 action193 升级胶囊从同一 PVF 导出使用条件与奖励。成长提交更新等级、经验及技能点并扣除原道具，涉及旧主线或等级支线时同步更新任务存档。

战令 C1767、C1768、C1772 使用账号级存档。赛季由 Gameplay 中的开始和结束时间配置控制。领取步进、领取等级奖励及购买经验通过事务过滤重复领取并投影 N1850、N1851、N1852、N1863。实际提交任务、副本击杀、无复活通关和疲劳扣除时写入对应计数。

宠物成长读取原 PVF 的 Bobi 等级表。在符合条件的清房首次提交 C39 时，同一事务核对先前阻挡怪物的死亡凭据、装备宠物实例与有效期，按表保存经验和等级并写清房收据。N102 在事务提交后发送。脚本销毁、未确认场景和重发的清房结果不累计成长。

C1421 按资产实例登记强化装备，N1361 返回当前登记及技能页。C44 伪装书扣减后，C211 依据本次使用凭据应用角色外观，C212 重置外观。C237 传送按 PVF 缺省落点或客户端坐标执行，扣票、冷却、位置和赛丽亚房间返回点在同一事务保存，C35 恢复城镇投影。

徽章 C201、C256、C907、C908 从 PVF 读取颜色、合成奖池及装备孔布局。镶嵌、开孔、合成均绑定原资产实例。C206、C451、C490 更新装扮孔、能力或颜色，保留原装扮及详情身份。C202 按装扮和已镶徽章的总分从资源奖池发奖。C99、C1113、C1787 使用原配方及产物选项，同时扣费并提交装扮。C1787 的累计能量保存在账号并通过 N1929 返回。C1786 用原套装效果规则投影会话外观。C857 以及 C507 action230 使用各自的槽券打开光环或宠物装扮槽，保留当前穿戴。

离线用例检查答题、C34 收据回放和技能购买与重置。新增交付、成长、战令、训练与徽章路径的 PostgreSQL 事务、客户端回包和完整实机流程待验收。
