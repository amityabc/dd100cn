# 启动器、GM 与资源工具的交互对照

当前 Go 版通过自有多人启动器接入解压客户端。除了频道与游戏 TCP，原项目还有命令行、进程就绪文件和 GM 本机管道。各入口的迁移状态如下。

| 调用方 | 旧接口约定 | 当前核对结果 |
| --- | --- | --- |
| 解压客户端的 `Start-Client.ps1` 和 `LocalTools/DNF100Launcher.exe` | 在玩家电脑读取配套启动配置并连接固定本机端口。频道 7001，城镇 10019，自由决斗 10501，排位 10252，洞察 10063。 | 自有启动器绑定五个原端口，再经 TLS 连接指定账号。实际用原脚本执行 CheckOnly 和 PrepareOnly，并用正式 Go 端口收取原始应答。[测试记录](../go-server/tools/multiplayer/README.md) |
| 源码树与发布包的服务管理器 | 读取 `runtime/next-ready.json`。原字段为 `Schema`、`ProcessId`、`StartedUtcTicks`、`HostPath`、`HostSha256`、`RunId`、`ServerEventsPath`、`LocalEntry`、`LocalGmCommands`、`NativePartyNotices`、`NativeTownProfile140`、`ChannelPort` 和 `GamePort`。LauncherUI 还检查目标文件名为 `Serve100.Host.dll` 并核对 PID、启动时刻。 | 候选版开发脚本使用独立的 `go-ready.json` 和实例锁。原 LauncherUI 针对 Go 进程的管理兼容待验收。复制旧字段本身无法通过其进程检查。[写入方](../s9a1/Server/src/Serve100.Host/ClientLaunchPreparation.cs) · [读取方](../s9a1/ClientTools/LauncherUI/LauncherServerControl.cs) |
| 旧 Host 命令行与批处理 | 服务启动接受 `--root`、`--run-id`、`--bounded-console`。另有 `--request-stop`、`--prepare-client`、`--check-inputs`、`--evidence-root` 和独立的 `--create-release-database`。准备客户端的 stdout JSON 包含 `Outcome`、`Launcher`、`Project`、`Client`、`ProcessId`、`ClientUI`。 | 在独立实例目录直接运行新旧两个正式程序，`--request-stop` 的退出码均为 0，stdout 的 `Outcome=StopRequested`、绝对 `Path` 和停止文件的五个字节一致。配套游戏启动脚本沿原路径准备资源。源码包的其余管理命令及退出码仍需逐条迁移。[参数解析](../s9a1/Server/src/Serve100.Host/Program.cs) · [启动脚本](../s9a1/Tool/Start-Source.ps1) |
| LauncherUI 发金币、点券和邮件 | 原 UI 调用 `--gm-wallet <GUID>` 或 `--gm-mail <GUID>`，传 `--root`、`--account local`、`--character`、`--reason`，另传 `--cera`、`--gold` 或 `--template`、`--count`。独立 `--gm-cera` 用 `--operation-id` 传操作号。原服务通过限当前系统用户的命名管道提交到游戏会话。 | 旧 UI 按源码固定发送账号 `local`。多人游戏凭据绑定实际玩家。旧 GM 管道、钱包发放、离线邮件投递与其授权和重试语义仍待在 Go 实现，现阶段已验收的是已有邮件的展示。[原 UI](../s9a1/ClientTools/LauncherUI/Program.cs) · [原操作入口](../s9a1/Server/src/Serve100.Host/LocalGmOperatorService.cs) · [邮件](../s9a1/Server/src/Serve100.Host/LocalGmOperatorService.Mail.cs) |
| GM 目录生成工具 | `--gm-index --client <目录> --output <文件>`，可附 `--server-root`。输出使用 camelCase，顶层字段为 `version`、`generatedUtc`、`clientPath`、`pvf`、`imagePacks2`、`database`、`items`、`ready`。旧版直接从本地 SQLite 读取角色列表。 | 游戏资源准备目录和 GM 公开目录是两个用途不同的输出。PG 版的角色列表、物品目录、统计字段与老界面的互操作待验收。[旧索引生成器](../s9a1/Server/src/Serve100.Host/GmClientIndexCommand.cs) |

原 GM 回复的字段顺序和命名可从 `LocalGmOperatorReply` 核对。包括 `Status`、`OperationId`、`Reason`、`CurrentCera`、`Grant`、`CharacterRevision`、`AccountRevision`、`ReadBack`、`CurrentGold`、`WalletGrant`、`WisdomSupply`、`CurrentFatigue`、`MailGrant`。迁移时用同一操作号重放，核对返回 JSON、账号和角色的版本及资产落库结果。[回复定义](../s9a1/Server/src/Serve100.Host/LocalGmOperatorService.cs)
